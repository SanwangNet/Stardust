# Web Skill 执行流程 M3-D

## 原有实现和范围

此前 `ExtensionManifest.skills` 只有名称和简介，界面仅展示它们；没有 Skill 注册表、稳定 ID、启停、正文加载或请求注入。Web 的 M2 使用 `assembleContext` / `buildConversationContext` 组织近期消息和 Web 全局摘要；支持 Tool 的请求包含 Agent Core 产生的 system 指令，ToolRuns 另加目标引用。无 Tool 的既有分支直接使用当前上下文。现有预算按 UTF-8 字节加每条消息 32 字节估算，不是真实 tokenizer。M4-A 在 HTTP 请求开始时读取已发布的三条连接，前端草稿和 localStorage 不参与执行。

## 契约和信任

星核 Manifest 的 Skill 声明包含 `<starcore>:<skill>` ID、所有者、名称、简介、版本、正文 SHA-256、渠道范围、匹配关键词、默认启停和所需能力。声明可记录 Web 或 QQ 范围，本阶段只有 Web 执行接入。Core 启动代码必须额外提供具有相同 ID、所有者、正文哈希和完整声明哈希的 `SkillBinding` 及加载函数，单独修改清单、路径或流程不能创建加载入口。绑定由服务端代码装配，本次不提供文件系统路径读取、联网安装或第三方插件沙箱。当前内置星核没有 Skill 正文和绑定；测试的两个 Skill 仅在测试夹具中注入。

扩展管理器依据星核安装、启用、连接状态、Skill 启停和绑定一致性生成请求快照。管理页面可启停已声明的 Skill；取消启用、停用或卸载会使相应租约失效。不同星核 ID 分属命名空间；非法或重复声明不参与执行并报告契约警告，声明升级与可信绑定不一致显示不兼容。当前可执行范围仅支持声明 Web 且无额外能力要求的 Skill；需要其他能力的 Skill 不可用，Skill 内容不会给 Tool、数据库或 Channel 授权。

## 图和请求链

`STARDUST_WEB_SKILL_FLOW=1` 开启 Web 请求的 Skill 图，默认关闭。请求开始时，Core 固定 Skill 元数据、绑定、租约和服务端图定义；M4-A 的 Web 图快照保持原语义。Skill 根组接口为 `request:string`（模型请求准备）和 `result:json`（提供给模型请求）；内部依次是候选发现、每个 Skill 的可选候选连线、适用性选择、范围过滤、内容加载和预算处理。只有依赖输出的节点执行。没有 Skill 或没有匹配项是合法空结果。

选择规则是当前请求包含声明的关键词，或以空格分隔的 `@<skill-id>` 明确指定；服务端调用也可传递明确 ID。连接只提供候选资格，停用、无可信绑定、不兼容或范围不足都不能被连接放行。断开候选到选择器的连接后，该 Skill 的正文加载器不会调用；其他候选不受影响。必需节点端口断开时校验失败。图输出还须携带本次运行由预算节点生成的凭证，防止重新连线跳过必需处理阶段。当前连接只由服务端可信定义控制，UI 为只读，不扩展 M4-A 发布权限。

加载只针对已选择且可用的 Skill，每个正文最多 32,000 字节；校验非空及 SHA-256。取消、租约撤销、5 秒加载超时或校验错误会停止请求，不回退。加载完成后及 Tool 图执行后再次检查租约；一旦模型请求已经发出，现有运行链不能撤回外部操作。异步加载器必须遵守 AbortSignal，Core 不能强制终止不合作的函数。

预算按已有字节估算口径，扣除已构造上下文（含必要 system 指令），Skill 总额最多 6,000 字节。按声明顺序装入完整 Skill；放不下的整项跳过，不截断。生成的文本以独立 assistant 消息放在当前 user 消息之前，并标注为不能覆盖系统、身份、隐私及权限规则的不可信外部指南；纯文本不执行命令或访问链接。带 Skill 的 Tool 请求在加入 Tool 目标提示后再次检查同一消息字节预算；Tool schema 和后续模型生成的内容不在该近似预算内。提示词边界不能从根本上消除模型受恶意文本影响，实际 Tool 权限和审批仍由 Core 强制执行。

Skill 图运行在 M2 完成一次上下文组装之后，不重复读取或重组上下文；M3-A 决定提供哪些 Tool，M3-B 和既有审批流程决定是否允许执行。没有 Skill 输出时保留原有请求内容。QQ 请求、主动发送和 Web 发布连接均不改变。

## 验证与已知限制

`tests/skill-flow.test.mjs` 使用模拟加载器和模拟模型验证选择、按需加载、断线/重连、完整预算、取消、契约篡改、星核/Skill 生命周期、在途快照、真实本机 HTTP 注入，以及 Tool 不可用与审批拒绝。WebUI 真实流程画板展示只读 Skill 根组与内部阶段、声明/可用状态和开关；没有实时请求级选中状态。无头浏览器检查使用本机模拟服务。

后续需要在明确授权和信任审核后提供实际内置 Skill 与 Core 绑定、设计更精确的 tokenizer/总请求预算、考虑受控的发布模型及不合作加载器的隔离。QQ Skill、第三方沙箱、代码执行与 Skill 商店均未实现。
