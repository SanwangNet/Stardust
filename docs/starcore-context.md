# 星核上下文

Core 的 `ContextService` 从可信入口创建受限句柄。QQ 句柄绑定 Bot 账号、私聊或群聊及当前事件；调用方不再传入目标会话或人物 ID。`prepare` 持久化当前消息，返回当前事件的序列边界和有界短期快照；`saveReply` 记录生成的回复及可确认的发送状态。Web 句柄由受 `getWeb` 限制的本机请求创建，负责窗口准备、历史搜索及委托现有会话事务。Web 和 QQ 使用同一个服务实例，各自的句柄和快照独立。

完整上下文是已有 `conversations.sqlite` 中成功保存的消息和来源，不是完整平台聊天记录。短期上下文从同一份历史按会话和来源重新构建，不重复存储正文或完整模型请求。QQ 默认最多读取 50 条近期消息、窗口预算为 36,000 UTF-8 字节；Web 保留原来的完整轮次规则和默认 50 条限制，普通模型路径默认预算为 48,000 字节，使用历史工具与摘要组装时最多为 36,000 字节。两者均保留当前消息并按消息序列排列；这些是上下文窗口字节预算，不是完整模型请求的 Token 限额。QQ 群成员以当前会话内的稳定别名区分，名称和正文均是不可信数据。不同 Bot、群聊和私聊不会因 Person 关联而合并。

QQ 回复使用现有消息状态：发送前为 `pending`，成功为 `complete`，明确失败或未发送为 `failed`，结果不确定为 `unknown`。短期窗口排除 pending 和 failed；为兼容旧记录，历史 Agent 回复均提示送达未确认。崩溃后 QQ pending 保持排除，Web 原有恢复行为不变。Tool 执行和审批的内部结果不作为聊天消息写入。

QQ 的 model-only 与 Tool Calling 共用快照；search_history 仍是按需工具，并排除快照已包含的近期消息及当前序列边界之后的消息。Web 的短期窗口保留完整用户／助手轮次和原有预算，历史搜索保留 `web:default` 的跨 Web 会话权限。Web 的 Global Context 仍按既有流程和预算加载，流程断开时不会读取；QQ 不读取 Web Global Context。

已准入且实际收到的 `GROUP_MESSAGE_CREATE` 普通群消息可只记录、不唤起模型。原有 QQ Input Flow、来源检查、去重和限流仍生效；不支持或未获权限的事件不会被虚构或主动拉取。文件数据库工作在有界 worker 中，超时或不可用时仅使用当前消息；`:memory:` 不能跨进程恢复。
