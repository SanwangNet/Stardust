# 星核上下文

Core 的 `ContextService` 从可信入口创建受限句柄。QQ 句柄绑定 Bot 账号、私聊或群聊及当前事件；调用方不再传入目标会话或人物 ID。`prepare` 持久化当前消息，返回当前事件的序列边界和有界短期快照；`saveReply` 记录生成的回复及可确认的发送状态。Web 句柄由受 `getWeb` 限制的本机请求创建，负责窗口准备、历史搜索及委托现有会话事务。Web 和 QQ 使用同一个服务实例，各自的句柄和快照独立。

完整上下文是已有 `conversations.sqlite` 中成功保存的消息和来源，不是完整平台聊天记录。短期上下文从同一份历史按会话和来源重新构建，不重复存储正文或完整模型请求。QQ 默认最多读取 50 条近期消息、窗口预算为 36,000 UTF-8 字节；Web 保留原来的完整轮次规则和默认 50 条限制，普通模型路径默认预算为 48,000 字节，使用历史工具与摘要组装时最多为 36,000 字节。两者均保留当前消息并按消息序列排列；这些是上下文窗口字节预算，不是完整模型请求的 Token 限额。QQ 群成员以当前会话内的稳定别名区分，名称和正文均是不可信数据。不同 Bot、群聊和私聊不会因 Person 关联而合并。

QQ 回复使用现有消息状态：发送前为 `pending`，成功为 `complete`，明确失败或未发送为 `failed`，结果不确定为 `unknown`。短期窗口排除 pending 和 failed；为兼容旧记录，历史 Agent 回复均提示送达未确认。崩溃后 QQ pending 保持排除，Web 原有恢复行为不变。Tool 执行和审批的内部结果不作为聊天消息写入。

QQ 的 model-only 与 Tool Calling 共用快照；search_history 仍是按需工具，并排除快照已包含的近期消息及当前序列边界之后的消息。Web 的短期窗口保留完整用户／助手轮次和原有预算，历史搜索保留 `web:default` 的跨 Web 会话权限。Web 的 Global Context 仍按既有流程和预算加载，流程断开时不会读取；QQ 不读取 Web Global Context。

已准入且实际收到的 `GROUP_MESSAGE_CREATE` 普通群消息可只记录、不唤起模型。原有 QQ Input Flow、来源检查、去重和限流仍生效；不支持或未获权限的事件不会被虚构或主动拉取。文件数据库工作在有界 worker 中，超时或不可用时仅使用当前消息；`:memory:` 不能跨进程恢复。

## 长期记忆的来源与作用域

Full Context 是成功持久化的原始消息；Short-term Context 是当前会话的有界近期窗口；Global Context 是由交流材料综合的长期记忆，名称不代表对所有渠道开放。三者共用现有 SQLite 数据库。schema 11 将记忆的认知归属与使用范围分开：归属可表示 legacy、global、person、space 或 conversation；可见性可表示不可用、原有 Web 本机范围、特定会话或特定空间。空间范围目前只保存元数据，不开放读取；没有自动跨渠道共享规则。

原有 Web 条目迁移为 legacy / web_local，保持 ID、正文、来源和待处理任务；其他旧 owner 的条目默认为不可注入。Web 模型读取在 ContextService 的句柄内进行，先按 owner 和可见范围约束 SQL，再经 ContextAccessPolicy 检查；原有流程节点、相关性选择及预算仍然生效。QQ 暂不自动生成或加载长期记忆，也不能读取 Web 遗留记忆。

综合任务保留原有消息序号范围和实际历史搜索证据；内部来源查询通过消息与 History Provenance 取得作者类型、渠道、空间和身份。受信来源证明消息的出处，不证明文字内容或摘要为事实。新建的受限记忆还可直接关联原始 Message ID。创建时，Web 范围要求所有来源均为可信 Web 来源，会话范围要求所有来源属于该会话，空间范围要求所有来源具有该可信空间；无法满足时拒绝，删除直接来源会使记忆不再可见。模型输出不能设定人物或可见性。旧记忆没有完整修订正文；本阶段开始的综合更新保留被替换版本和原有来源。

人物主体是由 Core 明确提供的独立引用，与消息作者身份不是同一字段；不根据昵称、摘要文本或来源作者自动推断。身份转移、人物合并和拆分不会改写来源或扩大可见范围。人物记忆的多个直接来源若解析到不同的当前 Person，会标记为需要复核并停止模型读取；这只是保守冲突检查，不据此推断描述对象。更完整的主体确认和复核操作留给后续管理能力。

记忆 ID 是稳定主键，主题只是用于展示与检索的名称。去重使用 `(owner, topic, scope_key)`：`scope_key` 是 Core 建立记忆时主体类型和引用、可见范围类型和引用组成的 JSON 数组；SQLite 的 JSON 编码区分空值和字符串，不依赖分隔符拼接。不同会话、空间、人物或可见范围可以有同名主题，同一创建范围内仍会拒绝重复。创建范围键保持不变；来源删除等原因导致当前可见范围收窄时，不更改 ID 或合并原本来自不同范围的条目。将来如果允许人工更改主体或范围，必须明确处理其与创建范围键的关系。

Web 综合只选择当前任务合法范围的候选，以候选 ID 读取来源和写入修订；写入前再次检查 ID、范围和版本。模型仍只输出主题和内容，不能指定记忆 ID。已有同名但不同范围的条目既不会进入候选，也不会被覆盖。C3-B 可以复用来源查询、作用域元数据和策略边界，但仍需实现 QQ 的安全综合、任务来源校验与按可信句柄读取，不能将现有 Web 任务直接改成跨渠道任务。
