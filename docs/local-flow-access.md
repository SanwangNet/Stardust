# 本机流程编辑与访问边界

流程画板默认可编辑 `recent`、`global` 和 `search_history`。流程发布 API 使用本机访问策略，仍要求已完成初始化；写入必须是同源 JSON 请求，并保留 revision 冲突检查。Web 上下文和 Tool 执行图是否使用发布版本仍由各自的 Runtime 开关控制，与编辑权限无关。

后端对 `/api/v1/` 写入要求服务端监听地址、TCP 本地地址和实际对端地址均为回环地址；拒绝通配或非回环监听下的写入。Host 必须是受支持的回环主机且端口匹配实际监听端口，拒绝可疑的转发标头；请求携带 Origin 时必须与 Host 同源，跨站 Fetch 元数据被拒绝。流程发布写入及 Tool 审批还要求 Origin；常规本机非浏览器 API 客户端在其余接口可以省略 Origin。只读接口维持原有本机同源边界，无法确认写入路径时总览显示只读。

`npm run dev` 的 Vite 只监听回环地址。启动脚本每次生成随机、短期的内部代理传输凭据并分别交给后端和 Vite；Vite 仅对经自身回环连接、Host 和 Origin 检查且没有转发标头的请求覆盖添加凭据。后端核对凭据后才接受 Vite 的不同前端端口。该凭据不是用户身份或默认管理员口令，也不授予 Tool 审批。单独启动 Vite 而没有这次启动的后端配对时，写入保持只读。

## 信任限制

TCP 回环对端只能证明与后端连接的是本机进程，不能证明该进程没有把远程连接作为完全透明的代理转发。如果一个本机反向代理接受不可信远程连接，并有意剥除所有转发信息、伪造回环 Host/Origin，HTTP 后端无法与真正的本机客户端区分。**不要将 Stardust 或其 Vite 端口通过此类代理向不可信网络开放**；常见的显式 `Forwarded`、`X-Forwarded-*`、`X-Real-IP`、`Via` 等标头会使写入被拒绝，但并不能识别恶意透明代理。该边界也不隔离能够以当前用户身份运行的本机进程。

未来远程访问需要正式的用户身份、会话、资源授权、CSRF 防护及明确的可信代理配置；不能把本机策略或开发代理凭据当成账号系统。现有 Tool 权限、逐次审批、取消和发送限制继续由 Core 执行。
