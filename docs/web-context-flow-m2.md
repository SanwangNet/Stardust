# Web 上下文执行图 M2

开发开关为进程环境变量 `STARDUST_WEB_CONTEXT_FLOW=1`；默认关闭，改变后重启 Server。该开关只影响 Web 对话的上下文构建，不改变画板或 QQ 路径。程序内部可通过 `ConversationService` 第五个参数的 `contextFlow` 选择开关和可信定义，以便测试或由服务端装配；HTTP 请求不能指定图或这个选项。

定义在 `builtInWebContextFlow()`，根图通过 `context` 节点组传入当前消息并取得组装结果。子图中 `current.value` 分别连接到 `web-recent.trigger`、`web-global.trigger` 和 `web-assembler.current`；`recent.value`、`global.value` 分别连接组装器的可选 `recent`、`global`。删除后两条边中的任意一条，对应来源不被调度；重新连接即恢复。当前消息为必需输入；两个可选来源缺失时使用空数组。

端口采用 M1 的严格字符串及新增 `json` 值类型。`json` 只接受有限数字、字符串、布尔、null、数组和普通对象（不可循环）；组装节点接收已有的历史消息和摘要数据结构。节点类型和函数只由服务器注册，图不能更改端口定义或指定数据库、身份、渠道或作用域。

每次 Web 请求经会话服务确认当前会话的 `channelId=web` 和 `scopeId=web:default` 后，由 Core 创建限定于该会话的近期消息读取闭包，以及限定于 `web:default` 的全局摘要读取闭包。当前产品只有本地单一 Web 作用域，并没有多用户身份隔离机制；将来支持多身份时，必须先由 Core 鉴权并限定作用域，不能沿用客户端声明。最近消息只包含当前会话中完成的消息；全局来源只返回当前 Web 作用域的条目。近期和摘要节点不接收会话或作用域参数。

组装器直接调用现有 `assembleContext`；没有提供历史 Tool 的模型沿用原有 `buildConversationContext` 路径，也不会查询全局摘要。指令、来源过滤、角色顺序、完整轮次、字节预算与截断规则均来自原实现；全局摘要仍是标明不可信的 assistant 背景消息。图不调用历史检索 Tool，Tool 仍可由模型按既有策略发起；断开图中的来源也不会禁用这个独立 Tool。

运行前完整校验；无效图返回 `CONTEXT_FLOW_INVALID`，节点失败返回 `CONTEXT_FLOW_FAILED`，取消返回 `CONTEXT_FLOW_CANCELLED`。错误原因仅公开安全的结构错误或通用错误，不暴露数据源异常内容。失败不会回退到旧路径或发起模型请求。执行图运行期间保持会话忙状态，防止异步组装导致重复请求并发。HTTP 连接关闭可取消尚在组装的图，节点需协作遵守信号；此改动不改变已开始的 Tool Run 的生命周期。

断开全局来源只影响本轮输入上下文的摘要读取和注入。既有完成轮次入队及后台摘要综合仍照常运行，后台任务可能独立访问其存储。断开近期来源也不删除历史消息；按请求 ID 的去重、持久化与响应仍保留。开关关闭时继续使用原有组装路径。

M3 若要接入 Tool、Skill 或星核，需要先定义 Core 持有的可取消、可审计、按主体和范围授权的能力接口，并确保副作用仍经过既有权限与审批。M2 未实现这些执行节点，也未实现流程发布、画板转换或跨用户授权。
