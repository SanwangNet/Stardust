# 可执行流程内核 M1

M1 内核是独立的服务端库，没有 HTTP 接口，也没有接入编辑器。M2 已增加默认关闭的 Web 上下文接入，见 [Web 上下文执行图 M2](web-context-flow-m2.md)。图只是待校验的数据；节点实现和端口契约由可信的服务端代码注册。内核不是 JavaScript 沙箱，注册代码本身必须可信。

## 定义与契约

`ExecutableFlow` 包含版本、根图 ID 和图列表；每张图包含稳定节点 ID、有向边、显式输入输出接口。边以节点 ID 和端口 ID 指定起点、终点；单个输入端口最多一条边，输出可以扇出。`input` 接口绑定入口节点的 `value` 输出，`output` 接口绑定输出节点的 `value` 输出；节点组使用子图接口的 ID 作为父图端口。接口不允许重复绑定节点或重复端口 ID。多次使用同一子图各自执行，状态以组节点路径区分。

`FlowRegistry` 的可信注册项定义端口方向、类型、必要性、角色、配置校验和执行函数。M1 支持 `string`、`number`、`boolean`、`control`（固定值 `true`），M2 新增 `json`；类型必须严格相等，数据在运行时再次检查。控制端口与数据端口一样构成依赖；它不提供条件分支或循环。内置 `input`、`output`、`pass`、追加字符串的 `transform`、`merge` 和特殊的 `group`。自定义注册项属于可信服务端代码，图不能提供代码、端口声明或注册项。额外的节点字段会被拒绝。

整个定义先做结构校验，包括未使用的图：未知类型、错误端口、类型不匹配、重复输入连接、图中环、直接或间接的组引用环都会拒绝。M1 不支持拓扑循环；以后模型/Tool 迭代必须作为另行设计的受控执行契约，独立限制轮数、预算和取消。

## 计划与执行

默认目标是根图接口输出，也可显式提供目标节点 ID。从目标沿连线反向寻找依赖，并校验所选节点的必需输入；只有参与所选目标的节点才执行。连接到所选普通节点的可选输入也是依赖，断开后不再拉取其来源；必需输入断开则在任何节点执行前报错。仅靠输入可达而没有连接到目标的节点会跳过；没有任何入口依赖的普通节点不可执行。显式目标可选择没有连接到输出的有效节点。

组按实际请求的输出在子图中递归计划，只拉取这些输出依赖的组输入和父图分支。必要接口缺线报校验错误；可选接口未提供，但子图实际读取时，会明确报告缺少入口值。未连接的接口不应被视为默认数据。无效结构即使位于孤立分支也会被拒绝，孤立分支的必需输入不要求连接。

按拓扑顺序串行执行，每节点最多一次；调用前对定义做快照。入口值由调用方通过根图接口 ID 提供，缺值和运行时类型错误均明确失败。已连接的上游如果没有产出必需值，下游会失败。结果包含输出及带嵌套路径的 `succeeded`、`failed`、`cancelled`、`skipped` 节点状态；失败或取消后尚未执行的节点标为跳过。取消通过 `AbortSignal` 协作传播：节点必须遵守 signal；内核在节点返回前无法强制中止其内部工作。校验错误在执行前抛出，运行时错误通过结果返回。

## 信任与未来接入

布局、坐标、视图、说明节点和 localStorage 都不是执行配置。`FlowDraftConverter` 为将来的服务端适配器保留类型边界：转换输入和输出均不可信，转换后仍须调用服务端校验；M1 没有提供转换器，更不会自动执行画板草稿。不能根据说明节点标题、用户声明的端口或类型直接创建可执行节点。

M1 不向节点提供 Tool host、扩展管理器、权限或审批对象；声明 `sideEffect` 的注册项即使被选中也会以 `SIDE_EFFECT_UNAVAILABLE` 失败。注册代码可以自行访问进程资源，因此这不是对恶意服务端代码的隔离。将来引入实际副作用节点时，必须由可信 Core 接入既有权限、目标和审批流程，不能以连线、类型名或图参数授予权限，也不能直接调用扩展绕过 Gateway；在此之前不得放开该限制。

M2 使用单独的可信节点调用现有 `assembleContext`，并由 Core 提供范围受限的数据源；具体边界和开关见 M2 文档。流程发布、授权和画板转换仍未实现。
