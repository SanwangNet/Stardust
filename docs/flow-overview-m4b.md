# 统一主流程视图 M4-B

## 真实路径与组合视图

当前没有一个串联所有能力的主执行图。Web 请求进入会话后，按配置使用 M2 上下文图或原有上下文路径；启用时再运行 M3-D Skill 图；支持 Tool Calling 时使用 M3-A 图或原有可用性判断，模型随后可以不调用、调用一次或多次 Tool。Tool Call 才进入现有参数校验、权限、审批及执行链，M3-B 开关控制该链是否经过执行图；结果再返回模型。Web 完成的对话可登记后台摘要综合，它不等同于当前请求中的 Global Context 读取。

QQ SDK 事件由 QQ 星核接收；M3-C2 开关开启时，入站过滤和可选诊断通过 QQ 节点组执行，否则使用原过滤路径。通过后 QQ 使用当前消息、现有主 Agent 渠道处理和 QQ 回复链。QQ 尚未接入 Web Conversation、Global Context、Skill 图或 Tool 循环。Web 和 QQ 使用同一个主 Agent 主体配置，但并不因此具有相同上下文路径。

`flow-overview.ts` 依据当前服务端图定义、星核目录、开发开关、运行配置及已发布记录生成只读模块关系。总览的虚线是描述因果或条件关系的展示线，不是可执行的主图；布局坐标和浏览器保存的位置只负责呈现。实际子图依然来自 M1 `ExecutableFlow`、M2/M3 图及 Starcore Contract。用户可以逐层进入 Web 上下文、Skill、Tool 可用性、Tool 调用与审批、QQ 入站组和星核声明目录。模型、主体配置和后台任务以只读说明展示，不伪造图节点。

## 状态来源与权限

本机同源、初始化完成后可只读查询 `GET /api/v1/flow-overview`。接口不返回密钥、请求正文或请求级轨迹；状态表达查询时的服务器配置，不代表节点正在执行。它分别报告 Web 和 QQ 状态、开关、模型接口是否支持 Tool、可用 Skill 数量、当前 Tool 候选及发布版本。Tool 候选只按当前连接和已知 Core 配置推算，实际请求仍重新检查权限；尚未读取的设置标为请求时检查。

`STARDUST_WEB_CONTEXT_FLOW`、`STARDUST_WEB_SKILL_FLOW`、`STARDUST_WEB_TOOL_FLOW`、`STARDUST_WEB_TOOL_EXECUTION_FLOW` 独立控制各图；Tool 执行图开启会隐式开启 Tool 可用性图。QQ 的 `STARDUST_QQ_INPUT_FLOW` 在星核启动时读取。Skill 图开启不代表本轮已注入 Skill；没有生产正文时明确显示无可加载 Skill。星核停用、不兼容或未连接与图开关分别显示。

Web 上下文与 Tool 可用性图开启时使用 M4-A 已发布连接快照；相应执行图关闭时，发布记录仍存在，该图并不生效。在途请求继续使用原有请求快照。服务端显式传入的测试或嵌入式图定义仍优先，其对应连接在画板中只读。

本机单用户可直接保存、校验、发布和恢复；写入受本机连接、来源及代理检查和 revision 检查约束。只有 `recent`、`global`、`search_history` 三条连接可编辑，其他执行连接和总览关系只读。无法证明写入来自受信本机路径时，画板保留只读展示并拒绝写入。旧版浏览器 FlowDocument 与视觉布局均不作为服务端执行定义。

## 验证与限制

`tests/flow-overview.test.mjs` 验证服务端状态、模型能力、Tool 开关的隐式关系、QQ 启停、空 Skill、只读权限和发布生效边界。既有 M4-A HTTP 测试继续验证断线、重连和在途快照。`tests/flow-browser-check.mjs` 使用本机模拟模型与 QQ 星核检查总览、子图导航、草稿保留、端口与发布、只读模式、深浅主题、缩放和小窗口平移。

主图没有请求级节点轨迹、实时计数或运行中动画。小窗口默认保留可读缩放，剩余区域通过拖动平移查看。后续可在现有授权边界下增加真实请求级可观测数据和更细粒度的能力依赖状态；这些均不是本阶段的新执行能力。
