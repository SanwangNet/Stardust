# Starcore 流程声明 M3-C1

`ExtensionPackage.flow` 是版本化、只包含数据的 `StarcoreFlowContract`。声明包含所属星核、包版本、节点类型及节点组；节点具有命名空间 ID、类别、M1 端口与角色、能力要求及是否已绑定可信 Core 适配器。节点组包含只读 `ExecutableFlow`，输入输出接口沿用 M1 的 ID、绑定节点、必要性和来源/目标文案；目录返回的接口类型由绑定节点的同一份端口契约推导，避免复制第二份可能不一致的类型声明。当前组定义必须自包含所有嵌套子图，图 ID 与类型 ID 使用 `<starcore-id>:<local-id>` 命名空间；不支持跨星核组引用。

扩展管理器在启用时校验声明、协议、Manifest 版本、名称空间、端口、能力及图结构，复用 M1 检查连线、接口绑定、类型、重复输入和环。接口未与内部连通时生成警告；自然语言来源/目标不具备可自动证明的语义，不能仅靠文案推断授权。已启用声明由 `StarcoreFlowRegistry` 注册；目录在读取时依据已安装与启用状态重建。停用、卸载或不兼容时显示不可用，同时保留受信包内声明以供查看。启用后保存接口指纹，兼容的包版本更新可用，节点端口或组接口不兼容时阻止启用；没有自动迁移。

声明既不是代码也不是权限凭证。只有 Core 硬编码的可信绑定可标记可执行，本阶段唯一绑定为 Web 已有上下文路径；独立声明注册表的 `execute` 固定拒绝。真实 Web 请求仍走 M2/M4 的既有 Core 注册和权限路径，不会从 Manifest 动态加载函数。QQ 声明仅表达当前 QQ 星核的入站消息过滤，标为说明，不声称接入统一会话、全局上下文或图执行。新的受信打包星核可使用相同协议注册声明，不能获得其他星核、Tool、数据库或审批权限；第三方沙盒和运行时适配均未实现。

数据边界：`ExecutableFlow` 是 Core 可验证执行图；Starcore Contract 是能力提供者的声明；M4-A 草稿/发布版本仅包含三个经授权的连接选择；`FlowDocument` 与画板布局属于展示。Web 的声明视图从现有 M2 图与 Core 节点契约生成；M4-A 发布模式生效时，目录的 Web 视图采用当前已发布连接，避免出现另一份独立图。用户组织组和说明节点不因此变为可执行能力。

`GET /api/v1/starcore-flows` 提供本机只读目录，包含星核状态、运行状态、声明和警告，不包含适配器函数或秘密。M4-A 开发画板的“星核流程”允许双击进入子图、通过面包屑返回，并查看接口来源、目标、端口和不可用状态；它是只读声明视图，不添加可发布连接。M4-A 的三条可编辑连接及已发布版本保持独立并继续生效。

当前发布模型还不支持引用任意 Starcore 节点，因此不存在可被卸载静默替换的已发布 Starcore 依赖；卸载后受信包仍在时目录显示未安装，安装数据和草稿不由显示名删除。如果将来支持外部包移除和发布依赖，必须持久化依赖及兼容签名，在不可用或签名不兼容时阻止执行/发布或要求显式迁移。M3-C2 应新增由 Core 装配的限定作用域适配器接口，并单独验证授权、取消、生命周期和部署隔离；不能把本声明当成调用许可。
