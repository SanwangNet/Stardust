# Stardust / 星尘

独立 TypeScript 后端和 WebUI，支持单个 OpenAI-compatible 模型，以及项目内提供的 QQ 官方机器人渠道扩展。

WebUI 使用项目内自托管的 Noto Sans SC 可变字体，避免依赖用户设备预装字体或外部字体 CDN；字重范围为 100–900，字体文件遵循 OFL-1.1，许可文本随静态资源提供。

## 环境要求

- Node.js 22.12 或更高版本（推荐当前受支持的 LTS）
- npm（随 Node.js 提供）

## 运行

```powershell
npm install
npm run dev
```

开发时打开 **http://127.0.0.1:5173**。Vite 只提供前端资源，并将 `/api` 代理到 Stardust Server（默认 `127.0.0.1:8347`，端口由现有配置和环境变量决定）。两个开发服务默认只监听本机；Vite 固定使用 5173，端口被占用时会报错。`npm run dev` 为本次启动生成仅供 Vite 与后端使用的临时代理凭据，不需要用户配置或登录；后端仍检查本机连接、来源及代理标头。

CSS 修改通过 HMR 更新，不刷新页面；TypeScript 和 HTML 修改会自动刷新页面，避免重复注册事件或连接。修改后端源码后需停止并重新运行 `npm run dev`；前端修改不会重启后端。后端重启会断开 QQ Gateway 和在途请求，清除内存中的审批和日志；配置文件及密钥不会因此清除。

首次启动时，在浏览器打开终端显示的 WebUI 地址并按步骤完成初始化；也可在交互式终端按 Enter 开始向导，直接按 Enter 使用默认值，输入 `:q` 或按 Ctrl+C 取消。两种入口使用同一份配置，先完成的一方生效；初始化后服务继续运行。修改监听地址或端口需要重启，环境变量仍优先于保存的配置。

初始化后可在页面配置 OpenAI-compatible Chat Completions 的 API Base URL（例如服务的 `/v1` 地址）、模型 ID、超时时间和可选 API Key，保存后测试连接并使用模型对话。聊天文本保存在当前浏览器的本地存储中，刷新后保留，不会跨浏览器或设备同步；清除浏览器站点数据会删除记录。每次请求只发送当前消息，不携带聊天历史。连接测试也会发起一次模型请求，可能产生费用。

模型配置中的「扫描模型」使用已保存的服务地址和有效 API Key 请求 `/models`；选择或手动输入模型 ID 后需保存才能用于调用。修改服务地址或密钥后请先保存再扫描。服务商未提供兼容的模型列表接口时仍可手动输入。

扫描结果保存在当前浏览器，并按已保存的服务地址分别恢复。启用模型配置中的流式请求后，普通模型对话会逐步显示回复；Tool 对话仍在运行完成后显示结果，审批流程不变。

扫描结果按服务商提供的能力或任务类型分类；缺少信息时根据模型名称推测，不能判断的归入其他模型。分类仅供参考，不代表实际接口兼容性，所有模型仍可选择或手动输入。

「模型 → 日志」展示 Server、模型服务和扩展的近期运行日志，通过 SSE 接收新记录。可暂停页面更新、复制或清空当前显示；清空页面不会删除服务端缓冲区。日志只保存在内存中，最多保留最近 1000 条，Server 重启后清空；断线期间如果缓冲区已淘汰旧记录，页面会提示。

本机可直接使用流程编辑器和 Tool 对话，不需要临时管理员登录。需要外部操作的 Tool 仍由 Core 检查权限，并要求对具体操作单独批准。

QQ 跨渠道 Tool 审批默认关闭，生产 QQ 对话默认仍为 model-only。要启用审批管理，在启动 Server 的进程环境中设置 `STARDUST_QQ_APPROVAL_TOKEN`：使用 `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"` 生成 43 位随机凭据，并安全保存；不要提交凭据。在 Web 会话侧栏的「QQ Tool 审批」中输入该凭据，才能读取和决定审批。管理接口同时要求可信本机监听和来源检查；未配置有效凭据时拒绝访问。凭据不会由服务器回传或存入浏览器持久存储；持有凭据的本机进程仍可访问，应妥善保护。

QQ 的私聊、群聊 Tool 白名单均默认为空，运行和审批只保存在内存中，服务关闭或重启后不能恢复。生成结果与 QQ 投递独立记录，不会发送主动消息或复用过期的被动回复目标。

QQ 生产 Tool Calling 默认关闭。要在可信本机环境显式启用，启动 Server 的进程环境需同时设置 `STARDUST_QQ_TOOL_CALLING=1`、上述管理员审批凭据及范围策略：`STARDUST_QQ_TOOL_PRIVATE_ALLOW`、`STARDUST_QQ_TOOL_PRIVATE_SENDERS` 分别列出私聊允许的 Tool 名称和发送者；群聊需同时设置 `STARDUST_QQ_TOOL_GROUP_ALLOW`、`STARDUST_QQ_TOOL_GROUPS` 和 `STARDUST_QQ_TOOL_GROUP_SENDERS`。各变量均为逗号分隔的精确值，空值拒绝授权；群号与发送者条件同时满足，仍须通过 QQ 入站验证、Core 和每次操作的 Web 管理员审批。请将平台标识作为敏感配置保管，不要提交。缺少有效 Tool、凭据或身份匹配时继续 model-only。

被授权的 QQ Tool 运行与接收队列分离；模型结果生成后只尝试原消息的被动回复一次。发送时同时检查原消息期限、现有四分钟队列安全窗口和连接状态；过期则保留结果并显示不可投递，不进行主动发送。平台拒绝、网络未知和取消不会被记为投递成功，也不会自动重试。当前验证使用 Mock，不代表 QQ 平台已批准或保证任何发送方式。

在 QQ 官方机器人扩展的「Tool 管理」中启用 `send_message` 后，可在「模型 → 模型服务 → 模型对话」请求发送文本。模型只能使用近期实际入站消息生成的临时目标引用；同类目标存在无法区分的多个候选时要求澄清。发送前须在界面批准一次，可拒绝；审批最多有效五分钟，刷新可恢复本次浏览器会话中的运行状态。主动发送是否被允许由渠道平台决定，网络中断时发送结果可能未知，不会自动重试。

在「扩展 → 已安装扩展」添加 QQ 官方机器人，填写 QQ 开放平台的 AppID 和 AppSecret，保存后启用。连接状态显示在扩展页面；账号需要获得 QQ 平台的私聊及群聊机器人相应权限。向机器人发送私聊文本或在群中 @ 机器人后，扩展将消息交给当前模型，并使用原消息 ID 被动回复。模型调用可能产生费用，回复不包含对话历史。

- `npm run build`：TypeScript 编译并复制前端静态文件
- `npm start`：运行已构建的后端（需要先构建）
- `npm run check`：TypeScript 类型检查
- `npm test`：编译并运行基础 HTTP 测试

生产运行请先执行 `npm run build`，再执行 `npm start`，通过后端显示的地址访问 WebUI；生产服务不依赖 Vite。`npm run dev` 启动前会编译后端，按 Ctrl+C 停止开发服务。

## 运行约束

- 默认绑定 `127.0.0.1`，端口 `8347`，**没有登录认证，不能直接开放到不可信网络**。
- 可用 `STARDUST_PORT` / `STARDUST_HOST` 临时修改监听地址，例如 PowerShell：

```powershell
$env:STARDUST_PORT = '8350'
npm run dev
```

- 可将根目录 `.env.example` 复制为 `.env` 设置 Core 的监听地址；进程环境变量优先于文件。不要提交真实 `.env`。
- 普通设置可写入项目根目录的 `config.toml`（可参考 `config.example.toml`）；文件不存在时使用内置默认值，不会自动创建。监听设置优先级为进程环境变量 > 根 `.env` > `config.toml` > 内置默认值。
- 产品名称固定为 Stardust；旧配置中的 `service.name` 读取时会被忽略，下次保存配置时移除。服务描述和 WebUI 标题仍可配置。
- 程序内部可使用 `loadConfig()` 读取配置、`resolveConfig()` 合并环境变量，以及 `saveConfig()` 校验并保存配置。保存使用同目录临时文件替换原文件，不保留手写 TOML 注释；`server.host` 和 `server.port` 修改后需重启生效。仅支持已定义的普通配置字段，密钥、Token 等敏感信息应保存在 `.env` 中。
- 模型普通配置保存在 `config.toml` 的 `[model]` 表；API Key 单独保存在根目录 `.env` 的 `STARDUST_MODEL_API_KEY` 中，进程环境变量优先。页面留空密钥会保留文件中已有的值，勾选清除会移除文件中的值；进程变量存在时页面会提示覆盖。保存两份文件并非跨文件事务，若第二步失败，界面会报告部分修改可能已保存，需重新加载核对。
- 模型地址支持 HTTPS 和仅限本机的 HTTP；不跟随上游重定向。可在模型设置中选择流式上游请求（默认关闭），普通模型对话逐步显示回复；连接测试使用同一模式。普通对话不包含历史消息；Tool 运行仅在当前回合内暂存消息。服务默认仅绑定本机，不应开放到不可信网络。
- `SetupService` 为 CLI、WebUI 和初始化 API 提供同一份状态。缺少文件或 `initialized` 字段时视为未初始化；服务启动不会自动初始化。普通设置保存不能更改初始化状态。
- 扩展配置位于可选的 `env/<extension-id>/.env`，各扩展独立读取；目录或文件缺失时视为未配置，读取时不会创建它们。扩展 ID 使用小写字母、数字及连接符。
- 扩展包通过 Manifest 声明配置字段和受控的管理页面，Tool 由所属扩展声明并独立启停。安装、扩展启用及 Tool 启用状态保存在 `data/extensions.json`；旧独立 `send-message` 状态迁移到 QQ 扩展，已有明确 Tool 设置优先。保存配置时才创建扩展目录；禁用保留配置，卸载时可选择删除或保留。项目只加载随项目提供并已安装的可信扩展。
- QQ 扩展的 AppID 和 AppSecret 分别保存在 `env/qq-bot/.env`，敏感字段不会回传浏览器。QQ 扩展仅处理私聊文本和群聊 @文本，过滤重复事件、近期回复的回声及平台标记为机器人的发送者；处理队列最多 20 条，串行处理，每个会话每分钟最多接收 5 条。SDK 对部分事件不提供可靠的发送者机器人标记，无法完全识别所有其他机器人。消息由现有模型服务处理，尚无 Agent Runtime。
- 提供 `GET /api/health` 以及首次初始化用的状态和提交接口；页面没有伪造 Agent、记忆和模型数据。

## 目录

```text
apps/server/src/    TypeScript HTTP Server 和健康检查接口
apps/server/src/extensions/  随项目提供的渠道扩展
apps/web/src/       TypeScript 前端、CSS 和 HTML
scripts/            构建辅助脚本
tests/              HTTP 行为测试
```
